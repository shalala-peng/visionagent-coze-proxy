# VisionAgent · 视觉内容智能体生产线

> **一句话定位**：用户输入一句自然语言需求，AI 自动生成并真实执行一条完整的视觉内容生产线——覆盖素材入库、视觉处理、合规审核、审片到多平台发布，全链路真实调用模型 API，而非前端模拟。

**在线 Demo（实时调用 AI）**：https://shalala-peng.github.io/visionagent-coze-proxy/
**智能体直链**：https://www.coze.cn/store/agent/7672806993245192246?bot_id=true

---

## 1. 解决什么问题

视觉内容团队（电商、摄影、婚纱、餐饮）在"拍摄完成之后"面临大量**重复性流程工作**：每一批素材都要重新规划"先分类、再抠图、再生成场景、再过审、再分发至多平台"。核心痛点有三：

- **流程依赖个人经验**：资深同事离职后，流程方法论随之流失，新人难以复用。
- **工具割裂**：分类、抠图、出图、审核分散在不同工具，无法串联成一条完整流水线。
- **缺乏"审片—打回"闭环**：客户反馈不满意时往往从头再来，问题原因无法沉淀复用。

VisionAgent 的核心主张是：**将"每次临时编排的流程"沉淀为"一次搭建、反复运行、可存为模板"的可复用生产资产**。

## 2. 产品是什么

VisionAgent 不是单点工具，而是一套**视觉内容生产线的自动编排与执行引擎**：用户用一句自然语言描述业务目标，系统自动拆解并生成一条适配该场景的生产线（有向图），再逐节点真实调用对应模型与服务完成执行。

**同一个自然语言入口，可生成不同领域的生产线（示例）**：

| 用户输入 | 系统生成的生产线 |
|---|---|
| "把这批电商商品图抠图换白底，生成场景图，过审后发淘宝" | 素材入库 → 分类 → 抠图 → 场景生成 → 审核 → 多平台发布 |
| "上传这条探店视频，提取卖点写成小红书图文，审完发布" | 素材入库 → 视频理解（提取卖点） → 图文生成 → 审核 → 发布 |
| "婚纱客片修图，客户审片打回重做，通过出竖版发小红书" | 素材入库 → 分类 → 抠图 → 出图 → 审片台（打回） → 发布 |
| "生成品牌主视觉海报，输出朋友圈 / 公众号 / 官网三种尺寸" | 出图 → 多尺寸适配 → 审核 → 多平台发布 |

> 指令入口是开放的：电商、社媒图文、视频内容理解、品牌物料等视觉场景，均可由一句需求生成对应生产线，而非仅限于"图像处理"。

**以"婚纱客片线"为例，说明生产线如何逐节点真实执行**：

```
素材入库 → 图片分类 → 智能抠图（去背景） → 合规审核（预检）
   → 场景生成（出图） → 客户审片台（人工） ──打回──▶ 场景生成
                                   │通过
                                   ▼
                            多平台发布（小红书竖版）
```

上述链路由真实模型驱动：分类调用视觉理解模型、抠图调用通义万相、出图调用智谱 / 万相、审核调用规则引擎；执行至"审片台"节点时暂停等待人工确认，确认打回则从上游节点重做，确认通过后方可发布。

> 核心说明：从"拆线编排"到各视觉处理节点，**全链路真实调用模型 API**，而非前端模拟演示。

## 3. 能力如何转化为用户价值

以下不按技术能力罗列，而按"用户原本的痛点 → 生产线如何解决"呈现；真实程度如实标注，不夸大。

| 用户原本的痛点 | 生产线提供的对应能力 | 真实程度 | 解决到的程度 |
|---|---|---|---|
| 每次都要重新想流程、依赖资深员工个人经验 | 自然语言一键生成生产线，可存为模板复用 | ✅ 真实 | 把"个人经验"沉淀为"可复用资产"，新人也能跑标准流程 |
| 素材分类 / 理解靠人眼逐张看 | 图片分类与理解（通义千问 VL 真看图） | ✅ 真实 | 批量素材自动打标签，省去人工逐张识别 |
| 抠图换底靠 PS 手动、慢 | 智能抠图（通义万相去背景） | ✅ 真实 | 一句话出白底图，免去手工抠图 |
| 调色 / 风格化靠修图师手调 | AI 调色（万相重渲染） | ✅ 真实 | 按"ins 风 / 复古"等指令批量出风格化图 |
| 场景营销图要单独找设计师 | 场景生成出图（CogView / 万相） | ✅ 真实 | 一句需求出营销场景图 |
| 文案要另找运营写、风格不一 | 文案生成（文本模型） | ✅ 真实 | 按平台自动出小红书 / 抖音文案 |
| 过审靠人工凭感觉、易踩违规 | 合规审核（规则引擎） | ✅ 真实 | 发布前自动预检风险点 |
| 客户打回从头来、原因不沉淀 | 审片打回闭环（前端真实闭环） | 🟡 前端真实闭环 | 打回只重做上游节点，原因可记录复用 |
| 多平台尺寸 / 格式要手动改 | 多平台发布 | ⚠️ 编排可见 | 当前输出多尺寸预览，真实发布渠道待接 OAuth |
| 视频粗剪要专业软件 / 人力 | 视频粗剪 / 相册 | ⚠️ 模拟 | 一期不做真出片，出片引擎留二期 |

> 能力边界如实标注：标「✅ 真实」即运行时真实打到模型 / 服务；「⚠️ 编排可见」表示节点已编排、但后端未接真实服务，属主动分期决策而非隐藏未完成项（见 §4 决策一）。

## 4. 核心产品决策

### 决策一：视频 / 相册标注为"模拟"而非硬编
真实视频流水线需接 FFmpeg / 腾讯云 VOD 等媒资处理引擎，开发成本与当前 MVP 受众（静态视觉为主）不匹配。因此一期将视频 / 相册标注为"规划中 · 模拟"：调度逻辑真实跑通，出片引擎留二期。视频理解能力（Coze 豆包视觉）可用，但"真剪出片"不在一期范围。

### 决策二：视觉执行节点复用统一模型底座
抠图与出图均基于已接入的通义万相 / 智谱等视觉模型底座实现，无需为单一功能额外申请 remove.bg 等独立服务与 Key，**配置成本与边际成本最优**，也便于后续横向扩展更多视觉节点（如换脸、风格化）。

### 决策三：做"多 LLM 路由"而不绑定一家
基础大模型迭代快，绑定某家等于把产品命脉交出去。架构做成 OpenAI 兼容，填 `LLM_BASE_URL` 即可接任意厂商（DeepSeek / Kimi / 通义 / 本地 Ollama / 聚合网关），降低供应链风险，并能按场景切模型（纯文本用便宜的、带图用带视觉的）。

### 决策四：主动删掉"品牌中心"模块
该模块让 Demo 交互更复杂、讲解成本更高。MVP 阶段优先"讲得清"而非"功能堆砌"，故整体移除。

### 决策五：编排层做 Schema 校验 + 重试
LLM 返回 JSON 常缺字段 / 格式漂移。加了宽容自动修正 + 带错误反馈重试一次，把降级概率压到最低——把"AI 不可靠"当成产品问题去解决，而非回避。

### 决策六：双模式主路径 + 行业灯塔模板
生产线的"画布"抽象对真实创作者（电商运营 / 婚纱店老板）门槛过高——他们想的是"上传素材 + 说一句需求 + 看结果"，不是"理解节点与连线"。因此产品做**双模式**：极简模式隐藏编排，只留"行业 + 一句话 + 上传 + 一键运行"，编排在后台自动发生；专家模式才是完整画布。同时把"电商商品图"沉淀为**灯塔模板**（白底图 → 主图 → 细节图 → 场景图 → 平台规范预检 → 多尺寸适配），将行业 SOP 编码成可一键复用的资产——这才是通用工作流工具（Coze / Dify）难以替代的护城河。

### 决策七：审片反馈记忆（拒因沉淀，越用越懂你）
审片打回当前实现是"从上游节点重做"，但仅单次生效、不积累。因此增加**反馈记忆**：每次打回的批注原因沉淀到本地（按生产线归一化归类），下次同生产线运行时自动在运行日志提示"历史被打回 N 次，常见原因：…"，并把原因带入修正语境。这把"AI 会越用越懂你"的产品故事讲圆——是 AI 产品区别于"会调 API 工具"的核心信号，且无需大模型、纯前端即可实现。

## 5. 衡量指标与成本估算

以下为 MVP 阶段的**指标框架与成本计量方式**。运行记录中的成本已由后端按每次真实 API 调用返回的 `cost` 字段累加；表中数字为单环节估算参考价（随模型与用量浮动），用于说明产品已纳入量化考量维度，非精确财报。

**北极星指标**：单次指令成功产出"可交付视觉素材"的比例。

**过程指标**：
- 拆线成功率（NL → 合法生产线 JSON）
- 出图一次通过率（无需人工返修）
- 审片打回率（反映前面节点质量）
- 端到端平均耗时（秒）
- 单次生成 API 成本（元）

**单次生成成本估算（以"商品图生产线"为例：分类 → 抠图 → 出图 → 调色 → 文案 → 审核）**：

| 环节 | 模型 | 估算成本 |
|---|---|---|
| 拆线（NL → 生产线） | 扣子 / LLM | ≈ ¥0.01–0.05 |
| 图片分类 | 通义千问 VL | ≈ ¥0.002 |
| 智能抠图 | 通义万相 | ≈ ¥0.04–0.08（免费额度内 ≈ ¥0） |
| 场景出图 | 智谱 CogView / 万相 | ≈ ¥0.08–0.12 |
| AI 调色 | 通义万相 | ≈ ¥0.04–0.08（兜底 CogView 时 ≈ ¥0.1） |
| 文案生成 | 通义千问文本 | ≈ ¥0.001（可忽略） |
| 合规审核 | 规则引擎 | ≈ ¥0（接阿里云绿网后 ≈ ¥0.002 / 次） |
| **合计** | — | **≈ ¥0.18–0.35 / 次**（有免费额度可近零） |

> 商业化假设：若面向中小电商按"¥0.5–1 / 次"订阅制，毛利空间正向；具体定价需结合真实用量与客群验证。
>
> 注：当前 Demo 的运行耗时与成本已从"随机 mock"升级为"基于真实响应累加"；运行记录页统计面板基于本次会话真实运行数据计算。

## 6. 已知边界与验收结论

**术语统一**：全仓库已消除「底层模型」等易混淆表述——拆线环节称「拆线模型 / 编排层 LLM」，文本生成称「文本模型」，避免与「视觉模型 / 出图模型」混用。

**已验收（2026-08-13，live 端点 curl 实测）**：
- **模糊意图澄清**：输入「帮我搞点图」「我想做个视觉相关的东西」等模糊需求，后端在调用 LLM 前由 `isVaguePrompt` 本地拦截，直接返回 `clarify` 反问表单，**不依赖任何外部 Key、永不降级**；清晰需求（如「电商商品图，产品图做白底图发到小红书」）则进入拆线。
- **成本真实计量**：7 个 mode 的 `cost` 字段均由 SCF 真实返回（moderation 0 / copy 0.001 / classify 0.002 / image 0.1 / matting·color 兜底 0.1 / 编排 0.01），非 mock。

**当前运行边界（部署者须知）**：
- 若 SCF 环境变量 `LLM_PROVIDER` 指向的供应商余额不足（实测曾遇 402），清晰需求会退化为示例生产线；解决：将 `LLM_PROVIDER` 改为 `coze`（需配 `COZE_API_KEY`）或给该供应商充值。
- `matting` / `color` 当前为万相优先、失败兜底 CogView：兜底出图**不保证去背景 / 不保证按风格调色**，建议先用真实素材（先 upload 到 COS 再传 COS 公网 URL）复测万相。
- 多平台一键发布、视频 / 相册真出片为二期（见 §4 决策一、Roadmap）。

## 7. 技术架构

```
前端（GitHub Pages 静态页）
   │  用户自然语言需求 + 选模型
   ▼
腾讯云 SCF 云函数（编排代理层，Node 18 零依赖，代持所有 API Key）
   ├─ 生产线编排：扣子 / 多 LLM 路由（NL → 有向图）
   ├─ 视觉执行节点：通义万相（抠图 / 调色）· 智谱 CogView（出图）· 通义千问 VL（分类）· 规则引擎（审核）· 文本模型（文案）
   ├─ 素材：上传 COS → 公网 URL 喂视觉模型
   └─ 异常 / 无额度时自动降级，保证可交互
   ▼
视觉模型（看图）· 文本模型（拆线）· 图像模型（出图）
   ▼
前端画布渲染 → 逐节点执行 → 审片台 → 打回重做 / 通过发布
```

**设计要点**：① 密钥只在云函数环境变量，浏览器 / 仓库零泄露；② 不绑定任何 LLM 厂商（OpenAI 兼容）；③ 异常时自动降级保证可交互；④ 代理选型经 Cloudflare → Railway → SCF 真实踩坑取舍（国内可达）。

## 产品演进方向（Roadmap 视角）

当前版本已完成"能力验证"（6 节点真 API + NL→生产线 + 双模式 + 灯塔模板）。下一阶段主线是**从能力驱动收敛为任务驱动**：

- 🔴 **P0 锁垂直 + 定义交付物**：以"电商商品图"为唯一 beachhead 打透；每次运行产出可复用"内容包"（白底图 / 主图 / 细节图 / 场景图 / 文案 / 多尺寸），而非仅"跑了一波"。
- 🟡 **P1 风格一致性 + 发布闭环**：以参考图 / 品牌规范约束生成保证同店视觉统一；补齐至少 1 个渠道的发布闭环，把价值变现最后一环从 mock 做实。
- 🟡 **P1 后期 团队协同**：共享模板库 + 审签流 + 角色权限，面向视觉团队多人场景。
